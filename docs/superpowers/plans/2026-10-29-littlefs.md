# LittleFS migration implementation plan

> **For agentic workers:** Use superpowers:executing-plans to implement task-by-task.

**Oku:** t-99; Task 1 t-100, Task 2 t-101, Task 3 t-102. Keep these open until merge into main.

**Goal:** Replace runtime FAT logging with the public littlefs-rust API.
**Architecture:** One synchronous filesystem owner on core 1; owned messages
to core 0; deadline/poison checks in every SD callback.
**Tech Stack:** Rust no_std, ESP HAL 1.2, esp-rtos 0.4, Embassy, littlefs-rust git main.
**Spec:** docs/superpowers/specs/2026-10-29-littlefs-design.md

## Global constraints

No automatic format, no hardware operations; exact dependency main in lockfile;
4096/512-byte geometry; preserve bounded shutdown and I2C mutual exclusion.

## Review focus

Wrong card must receive no writes; cancellation must forbid reuse; stale replies
cannot satisfy a new request; partial log writes must not discard pending data;
cross-core access must not move non-Send filesystem or peripheral objects.

Files: crates/theo-storage/src/littlefs.rs, littlefs_tests.rs, lib.rs, Cargo manifests/lock.
Interface: SectorIo sync read/write/sync; SdFilesystem geometry/config; log append/tail.
- [x] Write and run failing sector/actual filesystem tests.
- [x] Implement range checks, poison-on-error adapter and safe-API log functions.
- [x] Verify reopen, rotation, unformatted nonmutation, errors and capacity bounds.

### Task 2: Isolate the LittleFS storage owner

Files: src/device/sd.rs, sd_worker.rs, logging.rs, mod.rs; reusable request guard tests.
